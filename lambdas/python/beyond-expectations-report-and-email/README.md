# Beyond Expectations - Report and Email Lambda

This AWS Lambda function serves as the final step in the Beyond Expectations error monitoring pipeline. It aggregates analyzed error logs, generates comprehensive reports, and sends targeted notifications to both internal teams and clients.

## Overview

The Lambda provides the critical human-facing outputs of the error monitoring system:

1. **Data Aggregation**: Combines analysis results from multiple chunks
2. **AI-Enhanced Summarization**: Uses Bedrock Claude to create insightful summaries
3. **Report Generation**: Creates detailed HTML reports with interactive elements
4. **Visual Analytics**: Displays color-coded severity indicators and error trends
5. **Targeted Notifications**: Sends customized emails to support teams and clients

## Core Functionality

- **Comprehensive Error Summaries**: Consolidates error analyses across all logs
- **Bedrock-Powered Insights**: Leverages Claude for pattern identification and business impact assessment
- **Template-Based HTML Generation**: Uses Jinja2 templates for maintainable and reusable HTML/CSS
- **Client Communication Tools**: Generates pre-formatted mail-to links for follow-up communications
- **Multi-Channel Notifications**: Distributes notifications based on severity and audience needs

## Template Architecture

The Lambda now uses a template-based approach for better maintainability:

### Templates Directory Structure

```
/templates
  ├── email
  │   ├── internal_team_email.html
  │   └── client_email.html
  └── report
      └── error_report.html
```

- **Email Templates**: Located in `/templates/email`, these HTML files define the structure and style of the emails sent to internal teams and clients.
- **Report Templates**: Found in `/templates/report`, these files dictate the layout and design of the HTML reports generated by the Lambda.

### Jinja2 Templating

The Lambda uses Jinja2 for rendering HTML templates. It allows for dynamic content insertion and reusable HTML components. Key features include:

- **Template Inheritance**: Base templates define common structure (e.g., headers, footers), while child templates specify unique content.
- **Macros**: Reusable snippets for common HTML patterns (e.g., tables, alerts).
- **Static Files**: CSS and JavaScript files are served from the `/static` directory and linked in templates.

## Input

The Lambda accepts a JSON event with optional parameters:

```json
{
  "date": "2025-05-19",
  "notificationEmail": "support@beyond-expectations.com"
}
```

| Parameter | Description |
|-----------|-------------|
| `date` | (Optional) Date in 'YYYY-MM-DD' format for processing logs (default: current date) |
| `notificationEmail` | (Optional) Email for receiving the report (overrides environment variable) |

## Input Data Structure

The Lambda reads pre-analyzed logs from:
```
beyond-expectations/logs_analysed/YYYY-MM-DD/chunk-N.json
```

Each file contains categorized errors with severity assessments and notification requirements.

## Report Generation

The HTML reports include:
- **Executive Summary**: Top-level overview of error volumes and severity
- **Critical Issues**: Prioritized list of high-severity errors
- **Client Impact**: Breakdown of errors by affected clients
- **Error Categories**: Distribution of errors across different categories
- **Recommended Actions**: Specific steps for addressing identified issues
- **Detailed Error Logs**: Complete error details with context information

## Email Generation

The Lambda creates two distinct email types:
1. **Internal Team Emails**: Comprehensive summaries with links to full reports
2. **Client-Specific Emails**: Targeted notifications containing only relevant errors

## Configuration

The Lambda requires the following environment variables:
- `BUCKET`: S3 bucket for reading analyzed logs and storing reports
- `NOTIFICATION_EMAIL`: Default email address for analysis notifications
- `DEFAULT_SENDER_EMAIL`: Sender email address for notifications

## Key Components

- **S3 Integration**: Reads from and writes to S3 for data persistence
- **SES Email Delivery**: Sends formatted HTML emails with embedded reports
- **Bedrock Integration**: Uses Claude for intelligent summarization
- **HTML Generation**: Creates visually informative reports
- **Error Categorization**: Organizes errors by type, severity, and client

## Integration

This Lambda is the final component in the Beyond Expectations error processing pipeline:

1. **Format Error Logs**: Prepares and chunks logs for analysis
2. **Analyse Logs**: Processes each chunk for insights
3. **Report and Email** (this Lambda): Aggregates analyses and sends notifications

The Lambda completes the workflow by transforming technical error analyses into actionable business communications.

## Dependencies

- **boto3**: For AWS service interactions (S3, SES, Bedrock)
- **jinja2**: For HTML template rendering
- **bedrock-runtime**: For Claude integration
- **Shared libraries**:
  - `s3_helpers`: S3 utility functions
  - `helpers`: Common Lambda utilities
  - `bedrock`: Bedrock client configuration
